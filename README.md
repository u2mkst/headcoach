# 벤치에서 명장까지

감독이 되어 시즌마다 선택을 내리고, 그 결과로 커리어가 달라지는 **감독 성장형** 축구 시뮬레이션입니다.
한 경기 한 경기를 보는 게임이 아니라, 한 달 단위로 결과를 보고 전술을 조금씩 바꾸고, 보강 예산을 어디에 쓸지
정하고, 팬 지지도와 커뮤니티 반응을 살피는 게임입니다.

## 한 달의 흐름

한 시즌은 6개월(3월~8월), 한 달은 3라운드입니다.

1. **홈**에서 이번 달 결정을 확인: 전술(철학·포메이션·압박·수비 라인)을 조금 바꾸고, **전력 보강 예산을 어디에 쓸지** 한 줄로 정함
2. **N월 진행** → 3경기가 한꺼번에 진행됨
3. **월 보고서**: 결과 3경기, 순위·구단주 신뢰 변화, 보강 결과, **팬 지지도 변화**, 커뮤니티 베스트 글
4. 이벤트가 있으면 선택 (기자회견, 구단주 면담 등)
5. 반응 탭에서 가상 기사와 팬 커뮤니티 글 전체를 확인

선수는 이름 없이 등번호로만 구분하고, 개별 선수를 사고파는 이적 시장은 없습니다.

## 실행

```bash
npm install
npm run dev        # 개발 서버
npm test           # 엔진 테스트
npm run build      # 타입 검사 + 프로덕션 빌드
npm run balance    # 자동 플레이로 난이도 곡선 확인 (npm run balance 100 4 → 100판 × 4시즌)
```

모바일 앱 구조(한 화면에 한 가지 일, 하단 탭 5개)이며 데스크톱에서는 가운데 480px 폭으로 보입니다.

## 정해 둔 것 (인수인계 문서 5장 "먼저 정해야 할 것")

| 항목 | 현재 선택 | 바꾸려면 |
| --- | --- | --- |
| 기술 스택 | 웹 앱 (React + Vite + TypeScript) | - |
| 저장 위치 | 기기 저장만 (`localStorage`, 키 `headcoach.save.v1`) | `src/ui/store.ts`만 교체 |
| 첫 버전 리그 | 한 리그, 10개 구단, 2번씩 총 18라운드 | `src/data/clubs.ts` |
| 구단·대회 데이터 | 실제 이름 사용. 전력 수치는 **임의 값** | `src/data/clubs.ts` |
| 엠블럼·로고 | 파일이 없으면 구단 색 방패 + 첫 글자 자동 생성 | `public/assets/` 아래에 PNG 추가 |
| 공개 계획 | 없음 (공개·수익화 전 라이선스 확인 필요) | - |
| 선수 이름 | **쓰지 않음.** 등번호 + 포지션으로 표시 (예: "9번 공격수") | `src/engine/squad.ts`의 `playerLabel` |
| 시간 단위 | 한 달 = 3라운드, 시즌 = 6개월 | `src/engine/season.ts`의 `MONTH_ROUNDS` |
| 캐릭터 일러스트 | 아직 없음 (화면 문구는 직접 작성) | 미정 |

> **라이선스 주의** — 실제 구단·대회 이름과 엠블럼을 앱스토어 등에 공개하거나 수익을 낼 때는
> 라이선스 확인이 필요합니다. 그 전까지는 `src/data/clubs.ts`와 `public/assets`만 교체하면
> 한 번에 가상 데이터로 바꿀 수 있습니다. 화면 코드에는 이름·색·이미지 경로가 직접 들어 있지 않습니다.

### 엠블럼 이미지 규칙

- 구단: `public/assets/crests/<id>.png` (예: `club_001.png`)
- 대회: `public/assets/competitions/<id>.png` (예: `league_k1.png`)
- 정사각형 PNG(투명 배경, 256×256 이상) 권장
- 경로는 `src/data/clubs.ts` 한 곳에서만 참조합니다

## 구조

```
src/
  data/clubs.ts        구단·대회 데이터 (이름, 색, 엠블럼 경로)
  engine/              화면과 분리된 순수 함수. 같은 입력이면 같은 결과
    rng.ts             시드 난수 (상태가 숫자 하나라 저장 가능)
    squad.ts           선수 생성, 포메이션, 선발, 전력 계산
    match.ts           기대 득점 + 푸아송 득점, 철학 상성, 홈 이점
    season.ts          일정, 순위표, 전술 노출·숙련도, 라운드 시뮬레이션, 월 상수
    reinforce.ts       전력 보강 예산(공격·중원·수비·골키퍼·유소년·컨디션·저축)
    fans.ts            팬 지지도(감독 지지도·성적 만족·스타일 만족) 갱신
    events.ts          이벤트 9종과 선택 결과 (감독 능력치 판정)
    career.ts          시즌 결산, 재계약·경질·이적 제안, 오프시즌
    media.ts           월간 가상 기사·팬 커뮤니티 글
    game.ts            화면이 부르는 동작 모음 (playMonth 등, 상태를 복제해 새 상태를 돌려줌)
  ui/                  화면 (홈·반응·시즌·선수단·기록 + 시즌 진행 전면 화면)
  styles/tokens.css    디자인 토큰
```

게임 상태 전체는 JSON 하나로 직렬화됩니다. 이벤트처럼 코드가 필요한 데이터는 상태에 함수를 넣지 않고
`type`과 매개변수(id, 숫자)만 저장하며, 설명과 결과 처리는 `events.ts`의 함수가 맡습니다.
(`저장 상태에는 함수가 없다` 테스트가 이를 지킵니다.)

## 엔진 규칙 요약

- **리그**: 10개 구단 × 2번씩 = 18라운드, 승 3점 무 1점
- **경기**: 공격·중원·수비 전력 → 기대 득점 → 푸아송으로 득점 추출, 홈 이점 포함
- **전술 철학**: 공격 → 수비 → 점유 → 역습 → 공격 순으로 앞이 뒤에 강함
- **전술 노출**: 철학·포메이션·압박·수비 라인이 모두 같은 설정을 5경기 이어 쓰면 상대가 대응해 전력이 소폭(최대 3%) 하락
- **숙련도**: 같은 철학이면 경기마다 오르고(최대 +4%), 철학을 바꾸면 크게 떨어짐. 포메이션·압박만 바꾸면 노출은 초기화되고 숙련도는 유지됨
- **선수 상태**: 컨디션, 사기, 부상, 성장. 자동 선발은 컨디션을 반영. 선수는 이름 없이 등번호로만 구분하고, 득점자·경기 MVP·팀 득점왕 같은 개인 기록은 두지 않음
- **이벤트 9종**: 기자회견, 선수 불만, 부상 처치, 이적 제안, 구단주 면담, 유망주, 팬 항의, 라이벌 도발, 라커룸 갈등
- **장기 결과**: 유소년 기용 약속(21세 이하 출전 40회)은 시즌 끝에 점검, 무리한 복귀는 다음 시즌 기량 하락
- **시즌 결산**: 우승 / 기대 초과 / 목표 달성 / 미흡 / 실패. 유소년 육성·위기 극복·재정 안정은 성과로 인정해 한 단계 올려 줌
- **커리어**: 재계약, 경질, 타 구단 이동, 오프시즌 성장·은퇴·신인 영입
- **전력 보강 예산**: 달마다 한 곳을 고르고(조금 6억 / 보통 15억 / 많이 30억) 다음 달 진행과 함께 적용
  - 공격·중원·수비·골키퍼: 해당 라인 주전 평균보다 나은 선수를 한 명 영입(보통 +2, 많이 +4)
  - 유소년 투자: 시즌 끝 성장과 유망주 발생 확률에 반영 / 컨디션 관리: 그 달 회복↑ 부상↓
  - 예산 아끼기: 예산이 늘고 구단주 신뢰↑, 대신 팬 지지도↓
- **팬 지지도**: 성적 만족(승패·득실·목표 순위)과 스타일 만족(득점력·전술 철학·같은 전술 반복)에 보강 선택(투자 vs 저축)이 더해져 매달 변하고, 구단 수입과 구단주 신뢰에도 영향
- **커뮤니티 글**: 이번 달 결과·전술·보강·지지도에 맞는 주제(성적·전술·보강·감독)로 6개가 만들어짐
- **재정**: 라운드 수입에서 인건비를 뺀 값이 예산에 쌓이고, 시즌이 끝나면 순위에 따른 수입이 더해짐

## 밸런스

`npm run balance`는 네 가지 방식의 봇이 4시즌씩 플레이한 결과를 보여 줍니다.
프로토타입은 첫 시즌만 쉽고 이후 시즌이 어려워지는 경향이 있었는데, 지금은 시즌이 지나도 목표 달성 비율이 유지됩니다.
보강 없이 전술만 고정하면 계속 중위권(약 7위)이고, 매달 보강하면 서서히 올라갑니다(4시즌 뒤 평균 3~4위).
성장형이라 구단 목표도 전력 순위에 맞춰 같이 올라갑니다.
실제 구단 전력 수치로 교체한 뒤에는 이 스크립트로 다시 맞추세요.

## 배포 (GitHub Pages)

`main` 또는 `claude/build-as-is-n8h9eq` 브랜치에 푸시하면 `.github/workflows/deploy.yml`이
테스트 → 빌드 → Pages 배포를 실행합니다. 하위 경로(`/저장소이름/`)에서 서비스되므로
빌드할 때 `VITE_BASE`를 지정하고, 정적 파일 경로는 `src/data/clubs.ts`가 `BASE_URL`을 붙여 만듭니다.

- 최초 1회: 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 설정
- 로컬에서 같은 경로로 확인: `VITE_BASE=/headcoach/ npm run build && VITE_BASE=/headcoach/ npx vite preview`
- 주소: https://u2mkst.github.io/headcoach/
